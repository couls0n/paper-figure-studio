# 先路由图意，再选择论文视觉范式

重点能力是案例图、流程图和执行轨迹图。这批论文没有单一统一皮肤：TAI3 的紧凑对话对照、Task Shield 的运行循环、AgentDAM 的日志与截图证据列，依靠不同的布局组织论证。复用的是这些组织方式以及相应的视觉细节。

## 两步选择

1. 按表达目的与输入关系选 `comparison`、`architecture` 或 `trajectory`。先保留科学含义。
2. 按叙事方式、对象与证据数量选择本类的论文范式。记录一个主要原图锚点；其他论文只补充与它相容的细节。不要把多个来源的图标、字体和配色任意拼接。

| 叙事需求 | 默认 profile | 原图锚点与应保留的视觉组织 | 具体方法 |
| --- | --- | --- | --- |
| 同一请求怎样产生不同工具调用或结果 | `paper_case` | TAI3 Fig.1：并排用户气泡、浅蓝工具调用、局部差异、顶部变化关系 | [案例图](style/case-study.md) |
| 多个场景在两个条件下如何变化 | `paper_case` | BadAgent Fig.1/2：条件并列、场景逐行对应、角色与改动清晰 | [案例图](style/case-study.md) |
| 离线构建与在线执行如何连接 | `paper_flow` | TAI3 Fig.3、AgentAuditor Fig.2：阶段分区、异质对象、产物与反馈路径 | [流程图](style/workflow.md) |
| 守护器在哪里检查、放行或反馈 | `paper_flow` | Task Shield Fig.1/2：用户/agent/守护器/环境分区，路径承担语义 | [流程图](style/workflow.md) |
| 一次真实运行在哪一步产生关键变化 | `paper_trace` | AgentDAM Fig.2：任务/资料顶栏、时间列、等宽trace、截图及短注释 | [执行轨迹](style/execution-trace.md) |
| 执行过程还需逐步规则或JSON标注 | `paper_trace` | ShieldAgent Fig.7：左宽运行记录、右窄标注；Fig.14：历史截图与危险动作局部强调 | [执行轨迹](style/execution-trace.md) |

OS-Harm Fig.4 含有桌面截图，但主要关系是任务构造分支。是否出现截图不决定图型；一次运行的时间证据才构成执行轨迹。

## 写入绘图规格

```json
{
  "type": "comparison",
  "style": {"profile": "paper_case"},
  "style_reference": {
    "paper": "TAI3",
    "figure": "Figure 1",
    "page": 2,
    "preserve": ["paired dialogue", "role-specific bubbles", "local parameter differences"],
    "adapt": ["use the supplied case text and API name"]
  }
}
```

`style_reference` 记录视觉依据，`source` 记录内容和数据来源，两者不能混为一谈。模板使用原创示例内容，其数值与界面仍是 illustrative。来源定位和公开链接见 [逐图索引](corpus-index.json)。需要精确参考复现时实际打开对应原图；仅凭标题或图注不能确认视觉一致性。

## 怎样得到接近论文的 taste

- **先定轮廓与阅读顺序。** 小案例通常横向紧凑；方法图依阶段和返回路径安排；轨迹按证据列或主辅栏组织。不要先套等高卡片网格，再往里塞内容。
- **让对象有身份。** 对话是角色气泡，工具调用是等宽代码，资料是文档，记忆库是数据库，真实状态是截图。小型统一矢量图标辅助识别，正文标签仍承担主要含义。
- **颜色承担语义。** 浅灰/浅蓝/浅绿/浅橙区分角色、阶段或对象；红色集中在异常片段、危险动作与失败路径，绿色表示允许或任务相关内容。避免把整个失败条件涂成饱和红色。
- **保持论文的信息密度。** 缩小无意义内边距，减少重复标题，让同一比较关系处于同一视线。标题与正文的字号差异克制；日志/API使用等宽文字。密度增加必须以最终版面仍可读为前提。
- **按最终尺寸验字。** 明确单栏、双栏或附录整页的目标宽度，再检查最小标签。估算字号可用 `font_px / viewBox_width × final_width_mm × 72 / 25.4`；嵌入多面板还需乘面板缩放。复杂流程不应仅因槽位能放下，就缩成半栏小图。
- **线条解释关系。** 框线、细分隔线、虚线边界与箭头各有含义；反馈绕开节点，标注贴近对应对象。不要凭视觉对称补不存在的边或步骤。
- **保留关键证据。** 改动字符、实际工具参数、截图中的操作位置、首次异常步骤必须能直接定位。长说明可放图注，关键差异不能缩成不可读的小字。

## Visual review

将原图与生成图按相近显示宽度并排，逐项记录“保留 / 有意改变 / 需修正”，不以数值数据是否相同衡量风格。

| 维度 | 要检查的事实 |
| --- | --- |
| 轮廓与分区 | 横纵比例、主辅区面积、阶段/条件/时间的阅读顺序是否相近？ |
| 对象与语法 | 角色气泡、工具代码、资料/模型/数据库、截图和标注是否具有同样的视觉身份？ |
| 密度与层级 | 图内是否有过大标题、重复空白、过强标题色带；关键内容缩至目标版面后是否仍可读？ |
| 字体与颜色 | 正文与等宽内容区分是否合理；色彩面积和强调位置是否与来源接近？ |
| 连接与证据 | 边、返回路径、差异标记和callout是否指向正确对象，是否保留关键证据？ |

先修正前两项的大结构，再调整颜色、字号和边线。颜色相近但叙事布局不同，不能称为高一致度。截图缺失时可提供明确标注的布局样例，但不声称已还原真实运行证据。原图的装饰性阴影或品牌图标可以用统一矢量符号替换，并在适配说明中记录。
