## 初审发现与修改建议

### R1：修复轨迹中的机械断词与孤立标点

本次导出中，`trajectory.png` 第二列把 `field.` 断成 `fie` 与 `ld.`；第三列把句末句号单独放到下一行。`trajectory_annotated.png` 的 annotation 字符串中也出现 `m` / `odified.`、`remain` / `s.`。这些不是原论文的有意排版，而是固定字符预算换行的结果。

普通英语优先在词间空白换行，将尾部标点留在前词；长不可分 token 才降级到字符切分。JSON/动作文本应保留原内容与缩进，显示换行不要改变字段值。修复后同时看横向轨迹和窄 JSON 栏；不要只扩大一个例子的画布来掩盖通用问题。

### R2：加强纵向轨迹的步骤—标注对应

`trajectory_annotated` 已具备正确的左右框架，但所有右侧块连续堆在上方，Step 2 标注在左侧 Step 1 附近；最后一次执行证据与其标注缺少近邻关系。可采用每步共享垂直锚点、annotation 中的 step ID 标记或细灰色对应线，允许较长 annotation 向下延展。不要用粗彩色连线挤占截图区域。若有意采用来源图中的独立标注汇总栏，也应清楚标明这是按 ID 检索的汇总，而不是声称已逐行对齐。

### R3：把密度作为可调参数，而非一种固定“论文风”

流程图需要允许内容驱动的非等宽节点和较紧凑间距；纵向轨迹需要允许截图、观察和标注的面积随证据长度变化。目前的留白不会导致信息错误，但在双栏论文缩小后，疏朗布局会迫使文字进一步缩小。目标是维持关键对象与文字可读，不是照搬所有原图装饰。图像只展示少量模拟字段时，保持 illustrative 标识；使用实际截图时保留原始宽高比和可核对的局部标注。

### R4：在方法声明中区分已覆盖与尚需扩展的原图语法

当前 runtime 示例表达动作前审查和失败反馈，不是 Task Shield 全部工具输入/输出防护机制的复刻；多场景案例表达成对动作差异，不是 BadAgent 完整触发机制的复刻。两者作为原创可复用模板都成立。需要完整复现相关机制时，应让具体数据/连接规格补足因果或证据内容，而不是只改标题。TAI3 式参数表等异构对象也应按实际内容加入，不应作为无意义装饰默认出现。

## 审查边界

这次是六个新模板与指定来源图的独立视觉审查，不是所有可能内容长度、截图比例或模块数量的穷举测试。没有修改渲染器，没有替换原图，没有提交 Git。R1 为当前导出中直接可见的排版问题；R2/R3 为可读性和版式适配建议；R4 为模板表达范围说明。修复后的复验记录如下。
